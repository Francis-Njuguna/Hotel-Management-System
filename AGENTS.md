# HMS team working agreement

Start with `PROJECT_STATUS.md`. The owner requested an explicit stop after discovery. A proposal, a published Git commit and a rendered screen are not approvals. Neither the repository nor any field data is a source of approval by itself.

1. The principal owns the tracker and integration. Before delegating, record the objective and context, expected artifact, exclusive writable paths (or **none**), dependencies, acceptance criteria and verification method. Parallelize only independent work. Shared contracts, migrations and documentation each have one editor at a time.
2. During discovery, specialists review and report; the principal publishes. Project-local specialist profiles deny file edits, shell, Code Mode and nested delegation. At later approved gates, grant only task-specific access; do not relax machine-wide configuration. Explicitly pass the scoped files and source material: child sessions start fresh.
3. Distinguish **verified**, **required by brief**, **proposed**, and **unknown**. Keep raw interviews, participant identities, guest/payment records, unlicensed assets and secrets out of the public repository. Use synthetic, clearly labeled fixtures for later testing.
4. Every child reports (1) work completed, (2) files modified or none, (3) decisions/proposals, (4) checks actually performed and their results, (5) dependencies, (6) unresolved problems and (7) recommendations. Missing evidence is a blocker, not a pass.
5. The principal independently checks source material, reconciles conflicting reports and records acceptance or rework with rationale. Design the schema before models; review the data dictionary, ERD and contracts before implementation. QA and Security sign off independently of the implementers before handover.
